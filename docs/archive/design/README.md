# Archived Design Notes

These notes come from the development of the harness. They describe plans, not the current code. A check against the code on 2026-11-09 gave each note a status. Each note has the same status line under its title. For the current behavior, read [methodology.md](../../methodology.md), [results-schema.md](../../results-schema.md), and [tool-calling.md](../../tool-calling.md).

| Note | Status | What is still true | What is wrong |
|---|---|---|---|
| [managed-vllm-lifecycle-plan.md](managed-vllm-lifecycle-plan.md) | Implemented | `VllmServer` in `vllm_server.py` and `make_managed_server` in `core_runner.py`. Port check, own process group, SIGTERM then SIGKILL, `model_config.yml`, `resolved_server.json`, `vllm.log`, `--server-mode external`, separate spec servers. | The note uses the future tense. The focused tests of step 6 do not exist. |
| [architecture-flops-plan.md](architecture-flops-plan.md) | Implemented for Qwen3.6-35B-A3B only | `benchmarks/architecture_flops.py` writes `flops_analysis.json` with `exact_from_config` or `unsupported`. The 30 linear-attention and 10 full-attention layer layout. | `tests/test_architecture_flops_estimators.py` does not exist, and no test checks the formulas. Other models, for example Qwen3.8-27B, get `unsupported`. |
| [benchmark-upgrade-plan.md](benchmark-upgrade-plan.md) | Roadmap, partly done | Deep context, prefill scaling, TTFT breakdown, `--compare-spec`, concurrency, tool calling, and the GPU monitor exist. | No MTP acceptance rate is recorded. Deep context measures TTFT only at 32K and 64K. The TTFT split has two parts. The composite has no weights. The GB10 has 121 GB unified memory, not "32GB VRAM". Function paths in `core_runner.py` moved to `benchmarks/`. Items 6, 10, and 12 are not done. |
| [ttft-breakdown-plan.md](ttft-breakdown-plan.md) | Superseded | `benchmarks/ttft_breakdown.py`, `ttft_breakdown.json`, per-length aggregates and GPU windows. | vLLM reports no prefill time. The code makes a 2-way split (queue and post-queue), not the 4-way split of the note. `prefill_ms` and `first_decode_ms` stay `null`. The client is now in `harness/client.py`. |
| [tool-calling-plan.md](tool-calling-plan.md) | Implemented, with differences | `benchmarks/tool_calling.py`, 8 tools, six composite components, the multi-turn loop, and the task counts of the multi-tool (16), schema (20), error-recovery (17), and ambiguous (9) categories. | The composite is a plain sum from 0 to 6, not a weighted sum from 0 to 1. The tool results come from an in-process mock, not an HTTP mock server. `lite` holds 1 task per category, at most 8 tasks, not about 20. The task file has 16 categories, not 10. There is no "stress" set. |
| [moe-metrics-plan.md](moe-metrics-plan.md) | Not implemented | The questions that the note asks. | No MoE metric code and no `moe_metrics.json`. The estimator uses 256 experts and 8 per token, not 64 and top-2. `roofline.json` and `--skip-roofline` do not exist. |
