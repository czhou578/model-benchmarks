# Qwen3.8-27B NVFP4: Baseline Runs (November 2026)

This write-up covers four runs of `nvidia/Qwen3.8-27B-NVFP4` on the DGX Spark. Run D (era E4) is the current baseline. Runs A to C come from older eras; [Run D: the E4 baseline](#run-d-the-e4-baseline) compares run D with run C. [../comparability.md](../comparability.md) tells which runs you can compare. [../results-schema.md](../results-schema.md) describes the fields.

- Each comparable metric differs by about 2% or less. This agrees with the noise rule in [../comparability.md](../comparability.md#rules-of-thumb).
- Only one tool task changed result: `schema_title_max_length_fail`. It timed out at 120 s in run C and passes with the 600 s timeout of run D.
- With MTP, the token-based peak (38.35 tok/s) is above the mean. The per-event value of run C (9.59) was below the mean, so it was not a rate in tokens.
- All six reasoning prompts end with `finish_reason: stop` under the 4096-token cap. The palindrome prompt used all 1024 tokens of the old cap with 0 answer tokens. In run D, it thinks for 713 tokens and answers in 1716 tokens.
- The TTFT breakdown prompts have the exact row lengths: 128, 512, 2048, 8192, and 32768 tokens.

## Caveats

- The FLOP analysis gives `estimate_status: unsupported` for runs A to C. Their estimator knew only the Qwen3.6-35B-A3B dimensions. Run D has an estimate.
- Runs A and B predate PRs #67-#69. In these runs, the server TTFT split counted the queue time two times, and the energy used the old method. Run A also sent one shared prompt to every concurrency request. Do not compare the TTFT split, the energy, or the concurrency numbers of run A with run C.
- In run C, the task `schema_title_max_length_fail` failed on the old 120 s request timeout (`Read timed out. (read timeout=120)`). PR #73 later raised the default timeout to 600 s.
- With MTP, one stream event carries several tokens. The per-event peak, min, and median rates of the MTP-on server are not valid. Use the mean only. For example, the run C peak at 512 tokens is 9.59, below the mean of 24.47. Run D records token-based rates (`rate_method: token_delta`).
- With 85 tool tasks, the 95% confidence interval of a pass rate is about ±10 points. The difference between A and C (2 tasks) is inside this noise.
- Run A and run C differ in the vLLM version, the torch version, and the prefix-caching flag.
